이번 글에서는 재귀(Recursion)의 본질과 두 가지 필수 요소(기저 조건, 재귀 호출)를 다룬다. 재귀로 풀기 좋은 문제 패턴을 식별하고, 한계를 극복하기 위한 메모이제이션 기법까지 정리했다.

---

### 1. 재귀의 본질

#### 한 줄 정의

> **큰 문제의 답 = 작은 문제의 답으로 만들어낸다**

문제 안에 그 문제와 똑같이 생긴 더 작은 문제가 있을 때(자기-유사 구조), 재귀가 가장 자연스러운 도구다.

#### 함수가 자기 자신을 호출하는 구조

```python
def factorial(n):
    if n == 1:
        return 1
    return n * factorial(n - 1)   # 자기 자신 호출
```

함수 호출이 차곡차곡 쌓였다가, 가장 안쪽 기저 조건에서 답이 결정되면 거꾸로 풀려나오면서 최종 답을 만든다.

#### 콜 스택 (Call Stack)

함수가 호출될 때마다 컴퓨터는 **콜 스택**이라는 메모리 영역에 **프레임(함수의 작업 공간)**을 쌓는다. 함수가 끝나면 프레임이 빠진다.

- **LIFO 구조** (Last In First Out) — 마지막에 쌓인 게 가장 먼저 빠진다.
- 파이썬의 재귀 깊이 기본 한도는 **1,000번**이다.
- 한도 초과 시 `RecursionError: maximum recursion depth exceeded` (스택 오버플로우)가 발생한다.

#### 재귀가 어렵게 느껴지는 이유

> "`factorial(n - 1)`이 어떻게 답을 내놓는지" 머릿속에서 다 따라가려 하기 때문이다.

**따라갈 필요 없다.** 그 함수가 알아서 정답을 돌려준다고 믿고 결과만 활용하면 된다. 이게 "재귀적 사고(thinking recursively)"다.

### 2. 재귀 함수의 두 필수 요소

모든 재귀 함수는 두 부분으로 이루어진다.

| 요소 | 의미 | 빠지면 |
|---|---|---|
| **기저 조건 (Base Case)** | "더 줄일 필요 없음, 답을 바로 안다" | 무한 재귀 → `RecursionError` |
| **재귀 호출 (Recursive Call)** | "더 작은 문제로 줄여서 자기 자신 호출" | 그냥 일반 함수 |

```python
def factorial(n):
    if n == 1:                    # ← 기저 조건
        return 1
    return n * factorial(n - 1)   # ← 재귀 호출
```

#### 2단계 사고법 (재귀 함수 짜는 법)

거의 모든 재귀 문제는 다음 두 질문으로 풀린다.

1. **"가장 작은 경우는 뭐고, 그 답은?"** → 기저 조건 결정
2. **"n에 대한 답을, n보다 작은 답으로 어떻게 표현?"** → 재귀 호출 결정

#### 주의 — 두 가지 실수

1. **기저 조건이 없으면**: 무한 재귀 → 스택 오버플로우
2. **재귀 호출이 인자를 안 줄이면**: 무한 재귀

```python
# 잘못된 예 — 인자가 줄지 않음
def bad(n):
    if n == 1:
        return 1
    return n * bad(n)   # n - 1이 아닌 n → 영원히 갇힘
```

### 3. 재귀가 잘 맞는 문제 패턴

자기-유사 구조의 대표 사례는 다음과 같다.

| 구조 | 자기-유사한 부분 |
|---|---|
| 수열 (피보나치 등) | `a(n) = a(n-1) + ...` |
| 배열 분할 | 큰 배열 = 왼쪽 절반 + 오른쪽 절반 |
| 트리 | 트리 = 루트 + 왼쪽 서브트리 + 오른쪽 서브트리 |
| 폴더 구조 | 폴더 = 파일들 + 하위 폴더들 |
| 문자열 처리 | 회문, 부분 문자열 분할 등 |

#### 패턴 1: 피보나치 (분기가 두 개)

```python
def fib(n):
    if n == 0: return 0
    if n == 1: return 1
    return fib(n - 1) + fib(n - 2)
```

- 기저 조건 두 개 (n=0, n=1)
- 한 번 호출에서 자기 자신을 **두 번** 호출
- **중복 계산 문제**: `fib(40)`이면 약 20억 번 호출 → 메모이제이션 필요

#### 패턴 2: 회문 검사 (분할 패턴)

```python
def is_palindrome(s):
    if len(s) <= 1:
        return True
    if s[0] != s[-1]:
        return False
    return is_palindrome(s[1:-1])   # 양 끝 떼고 다시
```

- 한 번 호출할 때 문제 크기가 **2씩 줄어듦**
- 분할정복의 기초

#### 패턴 3: 빠른 거듭제곱 (분할정복)

```python
def power_fast(a, n):
    if n == 0:
        return 1
    half = power_fast(a, n // 2)
    if n % 2 == 0:
        return half * half
    return a * half * half
```

- 호출이 한 번에 절반씩 줄어듦 → **O(log N)**
- 단순 재귀(O(N))보다 훨씬 빠르다. n=10⁶이어도 호출 깊이는 약 20에 불과하다.

### 4. 재귀 패턴 A vs B — 결정적 구분

재귀에는 두 가지 본질적 유형이 있다.

#### 패턴 A: 결과를 조합(combine)하는 재귀

작은 답이 돌아오면, 거기에 **연산을 적용해서** 큰 답을 만든다.

```python
factorial(n) = n * factorial(n - 1)          # × 연산으로 조합
digit_sum(n) = (n % 10) + digit_sum(n // 10) # + 연산으로 조합
sum_to(n)    = n + sum_to(n - 1)             # + 연산으로 조합
```

#### 패턴 B: 문제를 변형(transform)만 하는 재귀

작은 답이 돌아오면, **아무 연산 안 하고 그대로 반환**한다. 인자만 변형되고 답은 한 번 정해지면 그대로 위로 올라온다.

```python
gcd(a, b) = gcd(b, a % b)        # 답 그대로 전달
```

#### 시각적 비교

**패턴 A — `digit_sum(1234)`**
```
digit_sum(1234) = 4 + digit_sum(123)
              = 4 + (3 + digit_sum(12))
              = 4 + (3 + (2 + 1))
              = 10
```
각 단계마다 + 연산으로 조합 → 최종 답이 만들어짐

**패턴 B — `gcd(48, 18)`**
```
gcd(48, 18) = gcd(18, 12)
            = gcd(12, 6)
            = gcd(6, 0)
            = 6
```
조합 연산 없음. 가장 안쪽에서 결정된 6이 그대로 위로 전달됨

새 문제를 만났을 때 가장 먼저 자문해야 할 질문은 **"이건 결과 조합형인가, 문제 변형형인가?"**이다. 이 구분이 명확하면 `return` 부분에 무엇을 적을지 자동으로 결정된다.

### 5. 메모이제이션 (Memoization)

#### 왜 필요한가

피보나치 같은 재귀는 **같은 값을 여러 번 계산**한다. n이 커지면 폭발적으로 느려진다.

| n | 메모 없음 (호출 수) | 메모 있음 (호출 수) | 배수 차이 |
|---|---|---|---|
| 5 | 15 | 9 | 1.7배 |
| 10 | 177 | 19 | 9배 |
| 20 | 21,891 | 39 | 약 560배 |
| 30 | 2,692,537 | 59 | 약 4만 5천 배 |
| 40 | 331,160,281 | 79 | 약 420만 배 |
| 50 | 40,730,022,147 | 99 | 약 4억 배 |

#### 핵심 아이디어

> "한 번 계산한 값은 dict에 저장해두고, 다음에 또 필요해지면 저장된 값을 그대로 꺼내 쓴다."

#### 직접 구현

```python
memo = {}

def fib(n):
    if n in memo:
        return memo[n]
    if n == 0:
        return 0
    if n == 1:
        return 1
    result = fib(n - 1) + fib(n - 2)
    memo[n] = result
    return result
```

#### 시간복잡도 변화

- 메모이제이션 없음: **O(2ⁿ)** — 호출이 두 갈래로 갈라지며 폭발
- 메모이제이션 있음: **O(n)** — 각 fib(k)는 단 한 번만 진짜 계산

`if n in memo: return memo[n]`이 빠르게 동작하는 건 **dict의 멤버십 검사가 O(1)**이기 때문이다. 자료구조 선택이 알고리즘의 효율을 결정한다는 게 이런 의미다.

### 6. 라이브러리 코너

#### `functools.lru_cache` — 메모이제이션을 한 줄로

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n == 0: return 0
    if n == 1: return 1
    return fib(n - 1) + fib(n - 2)
```

원본 코드에 `@lru_cache(maxsize=None)` 한 줄 추가만 하면 자동으로 메모이제이션이 된다. 파이썬 3.9+에서는 `@cache`도 가능하다.

#### `sys.setrecursionlimit` — 재귀 깊이 늘리기

```python
import sys
sys.setrecursionlimit(10**6)    # 100만으로 늘림
```

- 파이썬 기본 한도: 1,000번
- 코딩테스트의 DFS, 트리 순회에선 자주 필요하다. 너무 늘리면 스택 메모리 부족으로 죽을 수 있으니 보통 10⁶ 정도로 설정한다.
- **무한 재귀까지 막아주진 않는다.** 기저 조건은 여전히 필수다.

#### `math.gcd`, `math.lcm`

```python
import math
math.gcd(48, 18)       # 6
math.gcd(100, 75)      # 25
math.lcm(4, 6)         # 12  (파이썬 3.9+)
```

LCM과 GCD의 관계: **`lcm(a, b) = a * b // gcd(a, b)`** — 자주 쓰이는 공식이다.

### 7. 실전 문제 풀이 및 자주 하는 실수

#### 문제 1: 자릿수의 합

**문제 요약**: 양의 정수 N의 각 자릿수를 모두 더한 값을 재귀로 구하기.

```python
def num_sum(n):
    if n < 10:                       # 기저 조건 (한 자리)
        return n
    return n % 10 + num_sum(n // 10) # 마지막 자리 + 나머지의 합

n = int(input())
print(num_sum(n))
```

**사고 흐름 및 복잡도**:
- 재귀 패턴: A형 (결과 조합 — + 연산)
- 시간 O(log₁₀ N), 공간 O(log₁₀ N)

**막혔던 부분**:
- 기저 조건을 `n // 10 == n`으로 작성하면 의도(한 자리에서 멈춤)와 코드(0에서 멈춤)가 어긋난다. 기저 조건은 "가장 작은 경우에 정확한 답을 직접 반환"해야 한다.

#### 문제 2: 최대공약수 (유클리드 호제법)

**문제 요약**: 두 양의 정수 A, B의 최대공약수를 재귀로 구하기.
**핵심 정리**: `gcd(a, b) = gcd(b, a % b)`

```python
def num_gcd(a, b):
    if a % b == 0:
        return b
    return num_gcd(b, a % b)        # 패턴 B — 결과 그대로 반환

a, b = map(int, input().split())
print(num_gcd(a, b))
```

**사고 흐름 및 복잡도**:
- 재귀 패턴: B형 (문제 변형만)
- 시간 O(log(min(a, b)))

**막혔던 부분**:
- 원래 코드에 `return a % num_gcd(b, a % b)`처럼 패턴 A 사고를 적용해 `ZeroDivisionError`가 발생했다. 인자 변형과 답 조합은 다른 개념임을 명심해야 한다.

#### 문제 3: 계단 오르기 (중급)

**문제 요약**: N개 계단을 1칸 또는 2칸씩 오를 때, N에 도달하는 경우의 수.

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def stairs(n):
    if n == 1: return 1
    if n == 2: return 2
    return stairs(n-1) + stairs(n-2)

n = int(input())
print(stairs(n))
```

**사고 흐름 및 복잡도**:
- 점화식 도출: 마지막 한 걸음이 1칸이었나/2칸이었나로 분기 → `f(n) = f(n-1) + f(n-2)`
- 시간 O(N) (메모이제이션 적용 시), 공간 O(N)
- 메모이제이션 미적용 시 N=80은 사실상 풀리지 않지만, `@lru_cache` 한 줄로 0.001초 미만에 풀린다.

#### 자주 하는 실수 정리

| 실수 | 원인 | 해결 |
|---|---|---|
| 기저 조건 모호 | "재귀가 멈추기만 하면 된다"고 생각 | 가장 작은 경우의 답을 명확히 반환 |
| 패턴 A를 B 문제에 적용 | 둘의 구분 못 함 | "결과 조합 vs 변형만" 자문 |
| 손계산 실수 | 머릿속으로만 카운팅 | 종이에 작은 N부터 차근차근 도출 |
| 메모이제이션 누락 | 같은 인자 중복 호출 인지 못 함 | `@lru_cache` 자동 부착 습관 |
| 재귀 깊이 초과 | 1000을 넘는 호출 | `sys.setrecursionlimit(10**6)` |

### 8. 재귀 사용 시 체크리스트

재귀 함수를 짤 때마다 이 5가지를 점검해야 한다.

1. 기저 조건이 명확한가? (무한 재귀 방지)
2. 재귀 호출 시 인자가 작아지는가? (무한 재귀 방지)
3. 같은 인자로 여러 번 호출되는가? (성능 저하 방지 → `@lru_cache`)
4. 재귀 깊이가 1000 넘을 가능성이 있는가? (런타임 에러 방지 → `sys.setrecursionlimit`)
5. 패턴 A인가 B인가? (잘못된 return 형태 방지)
